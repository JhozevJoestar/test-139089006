# Решения и ограничения

- React + Vite + TypeScript, React Router, Tailwind CSS 4, Lucide. Отдельного backend нет. Все данные загружаются из Supabase; локального режима с фиктивными данными нет.
- Роль хранится в защищённой `profiles`, а не в редактируемых метаданных Auth. Профили создаёт только администратор через SQL Editor. Триггера, автоматически доверяющего метаданным регистрации, нет.
- Постановщики равноправны и видят все объекты и задачи. Исполнителем может быть только worker. Назначение обязательно. Автор задачи автоматически определяется через `auth.uid()` и не изменяется.
- Исполнитель видит собственный профиль и профили авторов/участников истории своих текущих задач. Постановщик видит все профили. Email Auth не выдаётся через profiles.
- Прямое редактирование разрешено только для содержательных колонок объектов и задач; колонки статуса, автора, ID и времени исключены из клиентских GRANT. Политики UPDATE дополнительно требуют manager.
- RPC работает с полномочиями владельца, фиксирует пустой search_path и использует квалифицированные имена. SELECT FOR UPDATE сериализует переходы по одной задаче. История записывается в одной транзакции; на создание задачи есть отдельный доверенный триггер.
- Принятый статус финальный. Постановщик может редактировать содержание или удалить принятую задачу, но не открывать её повторно: в ТЗ право CRUD не ограничено статусом. Переназначение сохраняет статус; прежний исполнитель теряет доступ к задаче и истории.
- Объект с задачами удалить нельзя (FK RESTRICT). Постановщик сначала явно удаляет задачи. При удалении задачи история удаляется каскадно. Удаление профилей с зависимостями также ограничено. Долговременного архива и soft delete нет.
- История хранит изменения статуса, но не редактирование описания или назначения. Для возврата отклоняются пустые и состоящие только из пробельных символов комментарии.
- Время хранится как timestamptz; UI отображает его по часовому поясу браузера. Статусы и подписи на русском. Поддерживается ограниченный объём данных: серверная пагинация и realtime не входят в текущую реализацию. Обновление выполняется после операций и при открытии рабочего пространства.
- На Vercel настроен SPA fallback. Публикация, привязка домена, резервное копирование и настройка Supabase остаются действиями владельца окружения.
- Проверки на встроенном PostgreSQL не заменяют облачные Auth/PostgREST и многосессионную конкуренцию. Для них есть отдельный `test:api`. Проверки браузерного сохранения сессии и маршрутов описаны в README; их нельзя считать выполненными без браузера и подключённого проекта.
